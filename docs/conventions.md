# Conventions

## Kotlin

- Kotlin official code style. Use 4-space indents and keep lines under about 140 characters.
- Use `val` by default and data classes for state. No `!!` in new code: use `?: return` or `requireNotNull` with a message.
- Keep functions small and name them after what they do (`refillOrders`, not `doOrders`). Comments say *why*.
- `core` must stay platform-free. Android or desktop specifics go in their launcher modules.
- Rules code (`model`, `world`) doesn't import `com.badlogic.gdx.graphics`, `scenes` or `audio`.

## Text and translation

- All player-facing text lives in `tools/i18n/strings.py` as `key: (English, Azerbaijani)`.
- Run `python3 tools/i18n/strings.py` to write `assets/i18n/strings_en.properties` and `strings_az.properties`. The Claude Code hook does this automatically.
- Placeholders are `{0}`, `{1}`, … Both languages must use the same set. Order can differ.
- Rules return `Msg(key, args)`. An argument can be a nested `Msg`, such as `Msg.item("egg")`, which is translated recursively.
- **English:** counts of items are written `Egg ×3` to avoid broken plurals.
- **Azerbaijani:**
  - Don't attach case suffixes to numbers or placeholders. `{0}-ə al` is wrong for `10`. Write `Al: {0}` or `{0}. səviyyədə`.
  - `-dək` is safe because it doesn't change with vowel harmony.
- **Glyphs:**
  - The font (Nunito) has Latin, Latin-1, the Azerbaijani letters and `× … • · – — “ ” « » ₼`. `Fonts.CHARS` lists them.
  - Arrows, stars, hearts and check marks are icons, not text.

## UI

- Build UIs with the widget kit in `Ui` and `PanelKit`: `button`, `roundButton`, `card`, `tab`, `item`, `info`, `stepper`, `detailHeader`, `lines` and `scroll`.
- Detail panes follow one pattern: a fixed header, then scrolling info lines (`ui.lines()` inside `ui.scroll`), then action buttons pinned at the bottom.
- Tables inside a growing cell must call `left()`, or their content centers.
- **Sizes** are in the 720x1280 portrait virtual UI. Lay panels out in one column: stack panes, don't put them side by side.
  - A layout must work from 3:4 (a 960x1280 stage) to 9:21 (720x1680).
  - Keep controls inside `ui.safe`, and keep the main actions in the lower half of the screen.
  - Touch targets are at least 52 px.
  - List rows are about 80 px.
  - Primary buttons are 64–68 px tall.
- **Colours:** use `Ui.INK`, `INK_SOFT`, `GOOD`, `BAD` and `GOLD`. Don't add new ad-hoc colours.

## Art

- Sprites are SVG strings built in `tools/art/src/*.js`:
  - terrain (dual-grid masks)
  - objects
  - characters
  - crops
  - icons
  - ui (nine-patches, at 2x)
- `node tools/art/build.js [filter]` renders them to `tools/art/out/` with headless Chromium. Install it once with `cd tools/art && npm install`.
- `./gradlew :tools:packAtlas` packs them into `assets/atlas/game.atlas`.
- **Style:**
  - Soft rounded vector shapes with gentle shading and warm colours.
  - Never pixel art.
  - Don't imitate another game's characters, tiles or UI.
- 1 tile = 128 px in the source art.

## Audio

- Every sound is generated by `tools/audio/synth.py`. Add a function, register it in `SFX` and add the id to `Audio.SOUNDS`.
- **Levels:**
  - UI ticks peak at about 0.3.
  - Actions peak at about 0.5.
  - Celebrations peak at about 0.65.
  - Music is normalized to 0.82 and played at 45% volume.
- Loops must be rendered with `wrap=True` / circular reverb so they don't click at the seam.

## Git

- Branches: `feat/…`, `fix/…`, `chore/…`, `docs/…`.
- Commits: an imperative subject of 72 characters or less, a body that explains why, and one logical change per commit.
- Generated files (`assets/i18n`, `assets/atlas`, `assets/sfx`, `assets/music`) are committed together with the source change that produced them.
